# 프로젝트: TOEIC RC 495 Vocabulary Mastery System

너는 숙련된 풀스택 개발자이자 제2언어 습득, 인지심리학, 어휘 교육, TOEIC Reading에 전문성을 갖춘 학습 시스템 설계자다.

내가 매일 사용할 수 있는 **TOEIC RC 495점 만점을 위한 개인 맞춤형 어휘 학습 웹 애플리케이션**을 실제로 개발하라.

단순한 단어 카드 앱이 아니라, 어휘 부족과 다의어 혼동을 해결하고 실제 영어 지문을 빠르고 정확하게 읽도록 만드는 장기 학습 시스템을 구축하는 것이 목표다.

기획서나 코드 예시만 제공하지 말고 실행 가능한 애플리케이션, 어휘 데이터, 학습 알고리즘, 테스트를 구현하라.

---

# 1. 학습자 프로필

현재 TOEIC RC 점수는 약 390점이며, 실제 시험에서 비교적 안정적으로 이 점수가 나온다.

최종 목표는 RC 495/495점이다. LC는 제외한다.

현재 강점:
- 기본 문장 구조 이해
- 능동태와 수동태 구별
- 관계절과 명사절 분석
- 주요 문법 규칙에 대한 지식
- 문맥을 통한 추론
- 객관식 정답 선택 능력

가장 큰 약점:

1. 영어 단어 자체를 처음 보는 경우가 많다.
2. 단어의 한 가지 뜻만 알아서 실제 문맥에 적용하지 못한다.
3. 업무 관련 연어와 관용적인 표현에 취약하다.
4. 문장 흐름을 대략 이해하고 넘어가는 경우가 있다.
5. 어휘를 몰라도 객관식 정답은 맞히는 경우가 있어 실제 이해 수준이 점수에 제대로 드러나지 않는다.

실제 학습에서 혼동했던 예시:

- quote: 인용하다 / 견적 가격을 제시하다
- receipt: 영수증 / 수령
- outstanding: 뛰어난 / 미결제의 / 미해결의
- settle: 정착하다 / 정산하다 / 해결하다
- reconcile: 대조하고 조정하다
- suspend: 일시 정지하다
- incur: 비용을 발생시키거나 부담하다
- refrain from: ~을 삼가다
- carry forward: 다음 기간으로 이월하다
- claim: 주장하다 / 청구하다 / 자리를 확보하다
- placement / replacement
- notice / notify
- amount / quantity
- dispatch / deliver
- return / refund / reimburse

최근 어휘 진단에서 불확실하다고 표시한 단어:

stipulate, impose, tentative, reconcile, remit, allocate, deduct, accrue, facilitate, designate, prospective, retain, procurement, expedite, contingency

이후 15개 어휘의 플래시카드 학습에서 12개를 안다고 표시하고 3개를 모른다고 표시했다.

최근 복습에서 틀린 단어:
- tentative
- prospective
- retain

단, 자기 보고에 의한 '안다'는 기록을 실제 숙달로 확정하지 말고 새로운 문맥에서 검증하라.

# 2. 가장 중요한 목표: 어휘 범위

단어 수를 임의로 1,000개로 제한하지 마라.

TOEIC RC 495점에 도전할 수 있을 만큼 충분히 넓은 어휘 데이터베이스를 설계하라.

다음 범위를 초기 설계 목표로 사용한다.

- 약 4,000~6,000개의 주요 표제어 또는 어휘군을 검토할 수 있는 규모
- 추가로 1,500~3,000개 이상의 중요한 연어, 관용 표현, 구동사, 업무 표현 후보
- 주요 다의어의 문맥별 의미
- 명사·동사·형용사 등 품사별 용법
- 파생어 및 관련 표현

이 숫자는 학습자가 새로 외워야 할 단어 수나 RC 495점 달성에 필요한 확정적인 기준이 아니다.

최종 규모는 실제 TOEIC RC와 유사한 영어 텍스트의 어휘 범위, 기존 학습자 수준, 중복 여부, 빈도, 문맥상 중요도 등을 고려해 결정한다.

**목표는 6,000개를 억지로 채우는 것이 아니라 RC 지문 이해에 필요한 어휘 공백을 최소화하는 것이다.**

표제어, 의미, 연어, 구동사는 별도로 관리하되 중복 학습량이 부풀려지지 않도록 한다.

어휘 데이터 구축 시 저작권을 준수하고, 실제 TOEIC 시험 문제나 유료 단어장 내용을 무단 복제하지 마라.

가능하면 신뢰할 만한 공개 어휘 자료를 조사하고 출처 및 라이선스를 기록하라.

빈도와 시험 출현율을 검증하지 못했으면 실제 측정값인 것처럼 제시하지 마라.

다음 분야를 균형 있게 포함하라.

2. 회계 및 재무
3. 은행과 결제
4. 인사 및 채용
5. 사내 공지 및 행정
6. 물류 및 배송
7. 구매 및 조달
8. 생산 및 품질관리
9. 영업 및 마케팅
10. 고객 서비스
11. 출장 및 교통
12. 호텔 및 관광
13. 시설 관리 및 부동산
14. IT 및 소프트웨어
15. 교육 및 행사

고급 업무 용어뿐 아니라 TOEIC에서 중요하게 쓰이는 일반 동사, 전치사구, 추상명사, 형용사도 포함해야 한다.

단어의 길이나 희귀함으로 난이도를 판단하지 마라.

흔한 단어라도 여러 의미 때문에 독해 오류를 일으키면 높은 학습 우선순위를 부여한다.

각 어휘 항목에는 가능한 범위에서 다음 정보를 포함하라.

- 표제어

- 난이도
- 학습 우선순위
- 업무 분야
- 핵심 의미
- 주요 문맥별 의미
- 각 의미를 구분하는 sense ID
- 한국어 자연스러운 뜻
- 대표 연어
- 필수 전치사 결합
- 혼동하기 쉬운 단어
- 단어 파생 관계
- 자연스러운 영어 예문
- 한국어 번역
- 예문 속 의미
- 흔한 오해
- 학습자의 숙달 상태
- 마지막 학습일
- 다음 복습일
- 정답 및 오답 이력
- 응답 시간
- 학습자 확신도
- 자료 출처 및 검수 상태

모든 의미에 무조건 여러 예문을 붙여 데이터만 부풀리지 마라.

중요한 의미와 혼동 가능성이 큰 용법에 예문을 집중하라.

예문은 TOEIC 스타일에 맞는 자연스러운 비즈니스 영어로 작성한다.

어색하거나 부자연스러운 예문, 문법적으로 잘못된 예문, 잘못된 한국어 번역이 데이터베이스에 들어가지 않도록 검증 과정을 구축하라.

# 5. 핵심 학습 기능

## A. 초기 어휘 진단

처음 앱을 실행하면 학습자의 어휘 수준을 진단한다.

처음부터 수천 개의 단어를 하나씩 확인하도록 요구하지 마라.

다양한 난이도와 분야에서 표본을 추출해 적응형으로 진단한다.

학습자의 응답에 따라 다음 문제의 난이도를 조절한다.

단순히 뜻을 알고 있는지뿐 아니라 다음을 구분한다.

- 단어 자체를 모름
- 단어는 알지만 해당 의미를 모름
- 의미는 알지만 문장에서 이해하지 못함
- 문장에서 이해하지만 회상 속도가 느림
- 새로운 문맥에서도 빠르게 이해함

객관식 문제만으로 어휘 숙달을 판정하지 마라.

## B. 인터랙티브 플래시카드

카드 앞면에는 영어 단어, 연어 또는 짧은 문장을 표시한다.

학습자가 답을 떠올린 다음 카드를 뒤집어 정답을 확인한다.

다음 평가를 기록할 수 있게 한다.

- 모름
- 틀림
- 어려웠지만 맞힘
- 정확하게 앎
- 즉시 이해함

학습자가 스스로 평가한 정보와 실제 테스트 정답률을 구분해 저장한다.

## C. 문맥별 의미 학습

가장 중요한 기능이다.

예를 들어 `quote`를 학습한다면 다음 차이를 이해시켜야 한다.

- quote a famous author
- quote a price
- the quoted amount
- request a quotation

각 표현을 개별적으로 무한 반복시키지 말고, 의미별로 적절한 문맥에 노출시킨다.

학습자가 특정 의미를 알고 있어도 다른 의미를 모르면 해당 의미만 집중 학습하도록 한다.

## D. 간격 반복 시스템

검증된 간격 반복 원리에 기반해 학습 일정을 관리한다.

FSRS 등 적절한 알고리즘을 사용할 수 있다.

다음을 고려한다.

- 정답 여부
- 자기 평가
- 반복 오답
- 경과 시간
- 기존 기억 안정도
- 필요하면 응답 시간

응답 시간이 빠르다는 이유만으로 정확성이 확인되지 않은 단어를 숙달 처리하지 마라.

틀린 단어는 적절한 간격으로 다시 등장하게 한다.

이미 충분히 숙달한 단어의 불필요한 반복은 줄인다.

## E. 문장 정밀해석 모드

실제 TOEIC Part 7과 유사한 문장을 제시한다.

사용자는 한국어로 직접 번역하거나 의미를 설명한다.

그다음 다음 사항을 확인할 수 있도록 한다.

- 정확한 전체 해석
- 의미 단위 직독직해
- 주어·동사·목적어·보어
- 관계절 및 수식 관계
- 핵심 어휘
- 의미를 잘못 선택하기 쉬운 부분

자동 채점 기능을 구현할 경우 단순 문자열 일치로 채점하지 마라.

한국어 표현이 달라도 원문의 의미를 정확히 전달했다면 정답으로 인정해야 한다.

AI 기반 의미 평가를 구현한다면 선택 기능으로 제공하고, API 키가 없을 때도 앱의 핵심 어휘 학습 기능이 정상 작동해야 한다.

## F. 장문 독해 모드

단어 암기에서 끝나지 않고 실제 지문 이해로 연결해야 한다.

다음 형태를 포함한다.

- 이메일
- 내부 공지
- 계약 안내문
- 고객 응대
- 청구서 관련 메시지
- 업무 기사
- 일정표와 이메일의 연결
- 이중 지문
- 삼중 지문

처음에는 정확도를 우선하고 이후 시간제한을 도입한다.

오답은 다음 유형으로 분류한다.

- 어휘 부족
- 다의어 선택 오류
- 문법 구조 오류
- 수식 관계 오류
- 시간 및 숫자 오류
- 논리적 추론 오류
- 단순 실수

문제를 맞혔더라도 확신도가 낮거나 근거를 잘못 이해했다면 복습 대상으로 기록한다.

## G. 개인 맞춤형 오답 학습

학습자가 틀린 단어는 이후 새로운 문장에서 다시 등장하도록 한다.

다만 같은 예문을 무한히 반복하지 마라.

새로운 문맥에서도 정확히 이해하는지 확인한다.

어떤 표현을 반복해서 틀리는지 대시보드에서 확인할 수 있게 한다.

# 6. 학습 대시보드

다음 데이터를 보여줘.

- 전체 어휘 데이터베이스 규모
- 진단 완료 어휘 수
- 학습한 표제어 수
- 학습한 개별 의미 수
- 숙달한 어휘 및 의미 수
- 복습이 필요한 어휘 수
- 오늘의 신규 학습량
- 오늘의 복습량
- 분야별 취약점
- 다의어 취약점
- 연어 이해도
- 어휘 학습 추세
- 문장 해석 정확도
- 장문 독해 정확도
- 독해 속도 변화

특히 **학습한 카드 수와 실제로 숙달한 어휘 수를 구분**해야 한다.

동일한 단어를 여러 의미로 배웠다고 해서 표제어 수가 중복 증가해서는 안 된다.

실제 TOEIC RC 예상 점수는 근거 없는 계산식으로 산출하지 마라.

점수를 추정한다면 별도의 충분한 모의고사 데이터와 검증된 기준이 필요하다는 점을 명시하라.

# 7. UX/UI 요구사항

앱은 한국어 사용자에게 최적화한다.

디자인은 깔끔하고 집중하기 쉬운 학습용 인터페이스로 제작한다.

필수 화면:

1. 학습 대시보드
2. 초기 어휘 진단
3. 오늘의 학습
4. 복습 대기열
5. 플래시카드
6. 문맥별 의미 학습
7. 문장 정밀해석
8. 장문 독해
9. 오답 노트
10. 학습 통계
11. 단어 검색 및 관리
12. 설정 및 데이터 내보내기

PC와 모바일 모두에서 사용할 수 있는 반응형 디자인을 구현한다.

키보드 단축키를 지원하고, 학습 중 불필요한 클릭과 화면 이동을 최소화한다.

오늘의 복습을 마치면 학습 결과와 다음 복습 계획을 보여준다.

다크 모드도 지원한다.

# 8. 기술적 요구사항

권장 기술:

- React + TypeScript
- 적절한 프론트엔드 빌드 도구
- Tailwind CSS 또는 동등한 스타일링 도구
- IndexedDB 등의 지속 가능한 로컬 저장소
- 필요할 경우 별도 백엔드 및 데이터베이스
- 단위 테스트와 브라우저 기반 E2E 테스트

기술 스택은 프로젝트에 더 적합한 구성이 있으면 변경할 수 있다.

최우선 조건은 다음과 같다.

- 실행 가능할 것
- 학습 기록이 유지될 것
- 인터넷 연결 없이도 핵심 학습이 가능할 것
- 데이터가 손상되지 않도록 설계할 것
- 수천 개의 어휘에서도 성능이 유지될 것
- 모바일 환경에서 편하게 사용할 수 있을 것
- CSV/JSON 등으로 학습 데이터를 내보내고 복원할 수 있을 것

사용자가 자신의 학습 데이터와 어휘 데이터를 소유할 수 있어야 한다.

# 9. 대규모 어휘 데이터 구축

이 프로젝트에서 가장 중요한 작업 중 하나다.

**데모 수준으로 단어 20~30개만 입력한 후 완료했다고 보고하지 마라.**

최종 목표에 맞는 대규모 데이터베이스를 구축할 수 있도록 실제 데이터 생성·검수·적재 파이프라인을 구현하라.

권장 작업 순서:

1. 어휘 출처와 후보 자료 조사
2. 표제어·어휘군 중복 제거
3. 중요도 기준 분류
4. 품사와 의미 분리
5. 문맥별 의미 정리
6. 연어와 파생어 연결
7. TOEIC 스타일 예문 생성
8. 예문과 번역 검증
9. JSON 또는 데이터베이스로 저장
10. 앱에서 검색·학습·복습 가능하도록 연동

한 번에 수천 개 항목을 무리하게 생성하지 마라.

품질을 유지할 수 있는 작은 배치로 나누어 생성하고 저장하라.

배치별로 다음 검증을 수행한다.

- 중복 표제어와 중복 의미
- 존재하지 않거나 부자연스러운 연어
- 잘못된 품사
- 의미와 맞지 않는 예문
- 잘못된 한국어 번역
- 필수 필드 누락
- 데이터 형식 오류
- 저작권과 출처 문제

자동 검증만으로 실제 언어적 정확성이 보장되지 않으므로, 불확실한 항목에는 검수 필요 상태를 부여한다.

**검수되지 않은 데이터를 검수 완료로 표시하지 마라.**

프로젝트는 데이터 구축 중간에도 실행 가능해야 한다.

먼저 실사용 가능한 앱과 높은 품질의 초기 어휘 데이터베이스를 완성하고, 이후 전체 목표 범위까지 데이터를 점진적으로 확장하라.

초기 데이터를 만든 뒤 중단하지 말고, 가능한 작업 범위 내에서 데이터베이스 확장까지 계속 수행하라.

단, 실제로 생성하지 않은 데이터나 미완료 작업을 완료했다고 주장하지 마라.

전체 데이터 구축이 한 번의 작업으로 끝나지 않을 경우, 현재까지의 결과와 미완료 배치를 기록하고 다음 작업에서 정확히 이어갈 수 있도록 체크포인트와 재개 가능한 스크립트를 구현하라.

# 10. 교육학적 품질 기준

이 앱은 단순 반복 암기를 넘어 다음 학습 원칙을 반영해야 한다.

**능동적 인출**

뜻을 바로 보여주기보다 사용자가 먼저 떠올리게 한다.

**간격 반복**

시간을 두고 복습하여 장기 기억을 강화한다.

**문맥 학습**

영어 단어가 실제 문장 속에서 어떤 의미로 사용되는지 학습한다.

**변별 학습**

혼동하기 쉬운 단어를 비교한다.

**전이 학습**

같은 단어를 새로운 문맥에서 이해할 수 있는지 확인한다.

**적응형 난이도**

기존 학습자의 실력을 반영해 너무 쉽거나 지나치게 어려운 어휘의 비중을 조절한다.

**정확성과 속도의 분리**

처음에는 의미의 정확성을 우선하고, 이후 이해 속도를 개선한다.

이 원칙들이 단순 설명이 아니라 실제 기능과 알고리즘에 반영되어야 한다.

# 13. 최종 교육 목표

학습자는 현재 TOEIC RC에서 약 390점을 받고 있다.

하지만 모르는 단어가 많아 영어를 정확히 이해하기보다는 문맥과 문제 풀이 감각으로 정답을 찾는 경우가 많다.

이 시스템의 목적은 학습자가 처음 보는 영어 지문에서도 다음을 수행할 수 있도록 만드는 것이다.

- 핵심 어휘를 즉시 이해한다.
- 단어의 문맥별 의미를 구별한다.
- 업무 관련 연어를 자연스럽게 이해한다.
- 문장을 대충 추측하지 않고 정확하게 읽는다.
- 여러 문장에 흩어진 정보를 연결한다.
- 정확도를 유지하면서 읽기 속도를 높인다.

TOEIC RC 495점은 최종 목표이지만, 어떤 단어장이나 앱도 만점을 보장하지는 않는다.

학습 결과를 실제 독해 수행과 모의고사로 검증할 수 있도록 설계하라.

**이제 계획 설명에 그치지 말고 프로젝트를 실제로 구현하라. 필요한 경우 독립적으로 개발 단계를 나누어 실행하고, 완성된 기능과 데이터의 품질을 검증하라.**
